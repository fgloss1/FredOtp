2.5 Money handling
All math in integer cents, server-side.
Browser never submits totals; it submits plan_id + optional zip_code + idempotency_key.
Server recomputes quote from nava_esim_plans row, writes snapshot into nava_esim_orders.
Wallet debit uses the existing wallet service inside a DB transaction with the order insert. Same idempotency key prevents double-charge on retry.
Refund path = existing wallet credit function + status = refunded.
2.6 Status machine (enforced server-side)
text

pending_payment
  → paid_awaiting_fulfillment   (wallet charged)
  → processing                  (admin picked it up)
  → active                      (admin confirmed real supplier activation)
  → failed_requires_review      (any step; triggers refund decision)

active
  → renewal_pending             (customer clicks Renew)
  → renewal_processing          (wallet charged for renewal order row)
  → renewal_completed           (admin confirms; expiry updated from supplier
